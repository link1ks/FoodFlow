# 工程边界与面试讲解

这些材料描述本仓库的实现与验证，不代表线上用户规模或生产SLA。讲解前应能独立运行测试、修改代码和解释失败路径。

## 1. 库存并发与幂等

**问题**：两个家庭成员同时做饭，共享同一批鸡蛋；请求超时后客户端可能重试。

**实现**：Handler完成家庭权限校验和参数解析；`idem`在同一个事务中锁定请求键并校验操作者、路径和请求摘要。`completeMealTx`接收明确的家庭与操作者范围，锁定餐次，插入具有家庭/日期/餐次唯一约束的完成记录，执行FEFO跨批次扣减、追加流水、调味品估算和补货建议，最后由调用方提交事务。

**为什么不只用幂等键**：客户端可能为同一餐生成不同键，因此还需要业务自然键。相同键换内容返回冲突，库存不足时整个事务回滚。校准用补偿流水，不能覆盖旧日志。

**验证入口**：`internal/app/v11_integration_test.go`、`pantry_test.go`、`v2_snapshots_test.go`。建议现场演示重复请求、两餐争抢和调味品过期触发回滚。

**可追问边界**：数据库超级用户仍可修改触发器；append-only是应用及数据库约束，不是防篡改密码学证明。事务服务仍在app模块，其他历史Handler尚未全部提取。多种兼容单位之间的全局FEFO排序应结合代码审查，不把单单位测试推广到全部场景。

## 2. Worker租约与失效写入

**问题**：模型运行期间Worker进程被杀死，新Worker接管后，旧进程或旧请求可能晚到。

**实现**：PostgreSQL任务表使用SKIP LOCKED领取、租约期限和令牌。完成写入需要同时匹配租约令牌和允许写入的任务状态。取消和结果提交由数据库条件约束决定先后。

**重试分类**：读取/计算可以重试；业务写入需要幂等；外部模型可能已经收费，不能承诺exactly-once，也不能将超时一律视为未调用。

**验证入口**：`internal/app/integration_test.go`中的队列恢复及失效令牌测试；运行前先搜索测试名称，检查数据库测试未被跳过。

**可追问边界**：数据库轮询会带来空闲查询成本；租约时长与续期频率是恢复速度和误判之间的权衡。没有实测瓶颈时保持单数据库架构，有积压与负载证据后再评估独立队列。

## 3. 模型输出与业务确认边界

**问题**：模型可能编造食材、输出不合法JSON、忽略忌口或对同一请求产生不同方案。

**实现**：模型只接收已授权库存、菜谱和偏好作为上下文；确定性代码负责数量、单位和库存校验，生成结果先作为待确认方案。确认时和做饭时分别重新读取库存，模型不能直接执行SQL或扣库存。

**验证入口**：`internal/agent/model_test.go`、`internal/app/nutrition_advice_test.go`及菜单集成测试。确定性假模型用于回归，未配置真实模型时明确展示演示模式。

**准确表述**：Eino模型接口适配 + 服务端受约束业务工作流。当前没有证据支持“多智能体自主协作”“通用智能规划平台”等描述。单次真实调用成功不等于准确率评测；后续需要固定案例集、失败率和成本统计。

## 简历示例

- 基于Go/Gin、PostgreSQL和React实现家庭库存与膳食规划闭环，采用批次行锁、餐次唯一约束、请求摘要幂等和追加流水保障并发库存写入。
- 实现数据库任务租约、取消检查和失效令牌写入拦截，使用Testcontainers验证异常与重试路径；真实模型调用采用人工确认边界。
- 将食材匹配及多菜/跨餐调度封装为纯内存模块，提供可重复Benchmark；性能数字须连同输入规模、硬件和测量范围引用验证报告。
