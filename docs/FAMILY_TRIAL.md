# 食光家庭试用

目标：先让一个家庭的两位成员完成“录入→安排菜单→采购→做饭→查看记录”，再根据实际使用负担调整。此文是试用操作说明，尚没有真实家庭研究结果。

## 启动与账号

已有 `.env` 与 Docker Desktop 的本地项目：

```powershell
pwsh -NoProfile -File scripts/local-trial.ps1 up
```

打开 [食光网页](http://localhost:5173)。该启动方式使用 `compose.trial.yaml` 显式覆盖模型、短信和菜价同步配置，使用确定性演示和本地照片存储；保存过的 API 密钥仍留在 `.env`，不会打印、覆盖或调用。关闭电脑后重新运行同一命令；不要删除 Docker 数据卷。首次配置见 [README](../README.md)。

已明确授权使用保存的 DeepSeek API 额度时，运行：

```powershell
pwsh -NoProfile -File scripts/local-trial.ps1 up -UseDeepSeek
```

该选项通过 `compose.trial-deepseek.yaml` 启用官方 HTTPS `deepseek-flash` 的文字与图片输入，菜单、营养建议和图片识别会产生 API 费用；两种模型使用同一 DeepSeek 端点与密钥，不沿用另一个视觉供应商的配置。短信、菜价同步仍关闭，照片仍保存在本地。密钥保持在 `.env` 中。再次运行不带 `-UseDeepSeek` 的 up 命令会恢复演示模式；status 显示实际运行服务的模型开关。余额不足或服务不可用时按页面错误处理。

真实模型连接检查须另行授权：`go run ./cmd/modelcheck` 会发送三次合成菜单/营养/图片请求，不读取个人厨房数据；通过仅说明这三个样本的调用与解析有效，不能证明真实照片准确率或持续推荐质量。完整 harness 和 CI 继续使用确定性 fixtures，不继承 `.env` 的模型密钥。

1. 用邮箱和密码注册，创建家庭并填写常用人数。个人主页可修改称呼、时区与提醒天数。
2. 另一位成员先用自己的邮箱注册。户主在家庭设置生成对应邮箱的邀请码，再让对方输入邀请码加入。需要记录库存选“编辑成员”；只查看选“只读成员”。两人看到同一个厨房，服务端决定权限。
3. 当前试用未开短信：可用邮箱/已有手机号加密码登录；短信找回、换绑与合并会显示不可用。不要把未配置短信误当作忘记密码流程已完成。已验证手机号找回和互补账号合并经过模拟服务验收，真实送达仍待授权验证；纯邮箱账号尚无自助找回。

## 三天试用步骤

| 时间 | 操作 | 需要核对 |
| --- | --- | --- |
| 第一天 | 录入冰箱中 5–10 种常用食材，选择真实照片对应的名称，填写余量、位置和知道的有效期 | 每批数量与原单位一致；不知道的有效期保持未知；记录录入花了几分钟 |
| 第二天 | 手工选菜、查看原料和步骤，填写用餐人数，确认菜单，购买缺口并确认入库 | 草案和推荐不扣库存；采购可以多买，但以实际买入数量确认；两人不要重复录入同一批购买 |
| 第三天 | 核对食材后完成烹饪、按需要记录报损，再查看库存流水和金额月报 | 只有明确完成才扣库存；重试不重复扣减；未知成本不是零元，月报显示覆盖情况 |

食材照片标有“参考照片”；家庭上传的实拍优先显示，加载失败会明确回退。16 道家庭菜谱的份量与步骤时长是参考，仍需按实际锅具和熟度判断。调味品免称重需要接受估算，并在余量变化后校准。

营养换算在食材批次的“营养换算 · 可食重量”中填写：例如称量两枚鸡蛋，去壳后净重 100g，则录入 2 个与 100g。只用于该批之后的原料营养估算，不扣库存，也不重算旧餐次。品种分类不清楚选“未知”；缺失营养参考仍然未知。记录的原料与人均份数不等于实际吃进肚子的量。

金额月报采用历史采购成本和出库快照。“本月记录采购金额”按录入日期计算，补录不会修改旧消耗。长图每页最多 40 组；导出前选择页数，其他页单独保存。不据此自动宣称省下多少钱。

## 观察与反馈

经成员同意后，仅记录下面的匿名观察，不收集密码、验证码、API 密钥或完整个人饮食记录。建议连续一周完成至少三顿闭环；以下是拟观察指标，不是已经达到的结果。

| 指标 | 记录方法 |
| --- | --- |
| 首次录入负担 | 5–10 种食材耗时、需要重复填写的地方、放弃原因 |
| 闭环成功 | 菜单确认→采购入库→完成扣库的实际次数与卡住位置 |
| 两人协作 | 重复录入/误扣次数、权限是否易理解 |
| 回访 | 第三天、第七天是否主动再次使用；没有使用的具体原因 |
| 数据理解 | 能否解释“未知成本”“参考照片”“营养估算”的含义 |

自动测试不能证明这些使用指标。当前质量台账仍保留 UX-TRIAL，收集实际反馈后再关闭。

## 数据与备份

数据库和本地照片保存在 Compose 命名卷。升级会运行新增迁移；账号合并与营养历史迁移拒绝自动降级，需要审查后的恢复方案。不要用删除卷或覆盖原数据库来尝试恢复。

对正在运行的本地厨房，可以将备份放在不参与 Git 的 `.cache` 中：

```powershell
New-Item -ItemType Directory -Force .cache/trial-backups
docker compose exec -T db pg_dump -U foodflow -d foodflow -Fc -f /tmp/foodflow-trial.dump
docker compose cp db:/tmp/foodflow-trial.dump .cache/trial-backups/kitchen.dump
docker compose exec -T api tar -cf /tmp/foodflow-trial-images.tar -C /app/data images
docker compose cp api:/tmp/foodflow-trial-images.tar .cache/trial-backups/images.tar
```

这两份文件分别保留数据库与图片，不是跨两者的原子快照；备份期间暂停录入和上传。恢复应先在新数据库和新图片目录验证，再决定切换，不直接覆盖现有数据。备份可能包含个人记录，仅保存在受保护的本机位置，不提交 GitHub。

## 本地验收范围

完整命令见 [HARNESS](HARNESS.md)。家庭负载场景使用独立 PostgreSQL、10 个虚构家庭、20 个并发客户端，持续 30 秒，每轮包含买入、同键重放、消耗、同键重放、库存/月报查询与跨家庭拒绝。目标为 0 请求错误、库存/流水/Outbox 守恒且 P95 小于 2 秒；每 100ms 采样数据库锁等待者。它包含应用与数据库，不包含公网、反向代理、缓存/Kafka 或真实模型，不能外推为生产容量。

复用验收镜像必须同时匹配源码摘要、构建时记录的不可变镜像 ID 与运行容器标签。门禁拒绝旧构建；本地标签/报告不是防篡改证明。真实模型效果、真实短信、S3、生产高可用与长期观察仍在单独范围内。
