# 工程反馈：真实评测、经验 RAG 与趋势

这是工程开发工具，不是用户菜谱/营养聊天功能。库存、权限、数量与幂等仍由确定性业务逻辑保障。本地 JSON 是开发证据，不是防篡改证明。

## 真实评测

日常 full/acceptance 使用固定模型、隔离真实数据库与桌面/手机浏览器。任务契约在最终验证前冻结业务范围、样本数、准确率与延迟阈值。失败后不能偷偷降低阈值。

`go run ./cmd/quality-eval -domain vision` 离线检查样例。明确授权后添加 `-paid -max-calls 4 -out .cache/harness/evaluations/<unique>.json`。支持 vision、speech、menu、rag。新日志独占创建，发送前持久化，无自动重试或恢复发送。不确定请求需要人工检查再决定新实验。

读取既有 `.env` 凭据但不写入日志。记录源代码、输入、样例集、提示词运行时和公开配置哈希，请求/返回模型名称、用量、耗时。精确模型版本、用量字段和账单拿不到时保留未知；token 不等于费用。非 200、超时不能算负例识别正确。

没有独立文本模型时，menu/rag 评测及 RAG answer 可以显式加 `-provider vision` 复用既有视觉模型的完整凭据对；不混用不同服务的密钥，也不修改默认应用配置。Qwen-VL 的文字调用参考[官方接口](https://www.alibabacloud.com/help/en/model-studio/partial-mode)；评测成功仅代表所记录模型，不代表尚未配置的默认菜单服务已启用。输入预检先检查全部媒体存在，再创建收费日志或发送请求。

`tests/fixtures/quality-eval.json` 是小规模公开/合成适配器验收集，不是独立标注的代表性用户评测。语音 WAV 在 `.cache/harness/live-inputs` 本地生成，不证明物理麦克风质量。扩大独立留出样例后才能评价泛化效果。旧标签、失败和各版结果保留。适配器通过不能代替数据库数量、重放及页面测试。

真实设备报告必须有操作人、设备/浏览器、步骤、预期和实际结果。合成音频与浏览器模拟不得标记成人工设备通过；本次必需但待验收的项目阻止完成。

RAG 原始模型评测默认使用 `-rag-prompt strict`，明确任意非空冲突列表均使该记录失去资格，包括引用记录缺失的情况；`-rag-prompt baseline` 保留 v0.3 原提示作历史比较。两者均不预先过滤评测输入，且不发送 `expected_answer`。新版提示不能改写旧留出分数；新冻结集见 [v0.3 修复样例](evidence/v030-rag-repair-corpus.json)，仍属小规模合成标签。

每个模型回答保存内容摘要；显式 `-retain-rag-response` 只在私有日志中保留限长、严格双字段的 RAG 回答，用于失败诊断，配置密钥和常见凭据标记被屏蔽。发布前仍须人工脱敏复核。评分拒绝重复键、多余字段、错误类型及尾随 JSON；不正确或覆盖不完整时先保留日志，再以非零退出码结束。

## 失败知识与 RAG

RAG 核心现在由嵌入的 Python 执行，使用 SQLite 倒排索引预计算归一权重；仍为 0.55 关键词 + 0.45 领域概念，阈值 0.15，最多五条，先过滤后精确排序。派生文件为 `index.sqlite`，升级需重新 index，历史 JSON 不迁移或删除。Python 同时拥有生成提示和严格引用/原文修复验证。Go 验证完整历史摘要和证据文件；纯索引延迟不能代替完整调用路径。规模/真实调用口径见 [执行计划](exec-plans/python-rag-scale.md)。

`go run ./cmd/harness -mode experience -action record -evidence .cache/harness/failure-input.json` 追加不可覆盖的修订。结构见 `cmd/harness/learning.go` 的 Failure：唯一 ID、任务、分类、需求/测试、数据条件、复现、代码/模型版本、环境、影响、负责人、证据和脱敏复核。resolved 还需确认的根因、修复、回归及页面证据。

`.cache/harness/experience/records` 是本地权威历史，禁止整体发布。公开内容只能另行审查后放入 docs/evidence。凭据模式检测不能替代人工脱敏；权限继承操作系统工作区账户，不提供多人共享服务或公开接口。

用新修订表达修复、失效、删除、替代和冲突。删除从当前检索和重建索引中排除，审计历史仍保留，因此禁止导入需要不可逆擦除的私人数据。索引摘要失配立即拒绝检索；`-action index` 可重建，无需模型调用。无回答缓存。

`-action query -evidence .cache/harness/query.json -out ...` 使用关键词余弦和显式领域概念向量，支持业务、故障分类、测试及已验证状态筛选，返回排序、引用、适用范围和版本差异。概念词表覆盖已知工程领域，不是通用预训练嵌入。无相关知识返回空结果。推测与冲突不能被当作已确认结论，也不能授权执行命令。

可用 `error_code` 和 `applicable_version` 精确筛选；经验的 `applicable_versions` 需明确声明，未声明不能视为匹配任意版本。当前 `code_version` 仍用于提示历史差异，两者不混用。查询中明显的凭据模式会被拒绝，发送前仍需脱敏复核。

query 输入包含 task、stage（start/failure/repair）、query、code_version、可选筛选及 disposition（采用/排除理由）。在绑定契约前查询历史，诊断后用 repair 查询记录决定。验证命令加 `-task <id>`，失败检查自动留档，不将原始命令日志复制到知识正文。自动初始分类仍需人工复核。

`-action answer -paid -evidence <query.json> -out <answer.json>` 对新检索结果进行一次真实生成调用。仅接受来自无冲突、已验证记录的原文修复及准确引用；编造引用、修改结论会被拒绝。无证据直接回答不足，无收费调用。这种保守生成不能判定当前根因或自动修复。

`-action evaluate -out .cache/harness/rag-eval.json` 在临时样例库验证精确/语义命中、无答案、筛选、版本差异、冲突、推测与过时知识。真实生成另外付费评测。通过只证明当前范围，不证明开放领域召回。

## 指标与每周复盘

批量真实 RAG 评测仅在明确授权后执行。`evaluate-rag-batch.py` 以同一私有账本串行预扣并发请求的费用上界，以供应商实际 token 用量按标价结算；不确定结果不释放占额，累计调用次数不退款，也不自动重试。实际账单与免费额度仍未知。评测带错误码/适用版本时，Python 在发送前及输出校验时使用相同资格规则。生成的数千种排列必须同时披露基础语义题目数量，不得称为数千条独立人工标注。

`-action metrics -out .cache/harness/metrics.json` 保留全部运行。旧报告无 task 时计入未知，禁止猜测归属。

完成门禁按规范化后的 JSON 内容比较指标，忽略对象键的序列化顺序；未关闭的其他任务问题仍保留在待办列表中，不能为了通过门禁而删除。缺失待办、RAG 历史或运行计数仍会被拒绝。批量脚本可用 `--task` 关联后续修复任务，但始终复用同一累计预算账本，不重置费用或请求数。

- 首次通过：同时观察到 full、acceptance 的任务为分母，两者首次均通过为分子。
- 返工代理：同任务额外 full/acceptance 次数，不声称等于人工修改次数。
- 不稳定候选：相同源代码、工具环境和浏览器项目下同名测试出现 pass/fail，尚需诊断才能认定 flaky。
- 复发：显式关联先前已验证根因，不能凭文本相似度认定；历史缺失不补造。
- 业务效果：保留样例集、模型、代码、耗时和费用状态，不把不同样例集直接比较成提升。

每周从频繁/严重问题建立有负责人、标准和回归要求的新任务。此实现不创建调度器。只有后续多次观察才能支持效率提升结论。

RAG 指标包括有结果查询数、版本不匹配结果数、检索与生成总耗时、引用约束通过的回答数、费用未知次数，以及保留的固定评测结果。检索非空不等于相关或正确；质量结论来自标注样例。门禁从完整当前历史重新计算并比较指标，拒绝占位统计和过时汇总；所有完成报告还必须关联当前 task。

## 完成门禁

新契约必须声明 feedback：业务评测范围及阈值、设备/RAG 必需性，或明确不适用原因。版本 2 完成包新增 feedback 报告路径。报告绑定任务、源代码和契约后的时间，包含评测、设备、RAG、指标和失败 ID。

未解决失败、缺失/过时证据、未查询历史、把未知费用当零以及待验收必需设备均阻止通过。原 full、acceptance、diagnose、main-site、当前发布提交 CI 门禁继续适用。
