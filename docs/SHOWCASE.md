# FoodFlow 虚拟动态演示

四段循环 GIF 用「简化界面 + 流程节点」演示 FoodFlow 的关键状态变化。画面、鼠标动作、数量和审核结果均由预设场景生成；GIF 内的按钮用于表达操作顺序。这些不是应用录屏，也不代表实际模型输出或真实用户数据。

## 食材入库 · 11 秒

![虚拟动图：语音线索形成可修改草稿，用户核对确认后创建库存批次和流水](assets/demos/intake.gif)

示例输入「番茄五百克，鸡蛋两个」。识别阶段形成待核对草稿，库存保持不变；用户确认后，番茄 500 g、鸡蛋 2 个连同入库流水一起记录。实际图片与语音识别能力需另行配置，详见 [识别范围](INTAKE_SCOPE.md) 和 [语音入库](VOICE_INTAKE.md)。

## 菜单 → 采购 → 烹饪 · 14 秒

![虚拟动图：读取库存、确认菜单、按缺口采购入库、确认烹饪扣库](assets/demos/plan.gif)

示例为 1 人份蒜香生菜，需要生菜 150 g、蒜 10 g。已有生菜 50 g、蒜 0 g，因此确认菜单后生成生菜 100 g、蒜 10 g 的采购缺口。核对采购并确认入库后，余额为 150 g / 10 g；再明确确认烹饪完成，才扣减至 0 g / 0 g。草稿、确认菜单、采购入库和烹饪扣库是不同步骤。

## 流水与金额月报 · 11 秒

![虚拟动图：从库存流水汇总已知成本、标明未知成本并导出月报](assets/demos/report.gif)

虚拟月报展示 8 笔记录采购金额 ¥38.00、已知消耗成本 ¥1.00、已知报损成本 ¥0.40。出库成本覆盖 2/3 条，一条未知成本保留未知；导出图片同时保留覆盖说明。不同单位分别展示，不以现价补齐历史成本，也不推算节省金额，口径见 [服务边界](PLATFORM.md)。

## 配方社区 · 12 秒

![虚拟动图：完善配方、同意初审、公开互动、候选经管理员确认收录](assets/demos/community.gif)

示例配方先是私有草稿，作者明确同意后提交初审。预设初审通过后公开，支持点赞与收藏；每周候选仍需管理员确认才能署名收录食谱库。审核异常时保持私有。这里的成功审核、互动和收录都是虚拟演示，实际规则见 [社区指南](COMMUNITY.md)。

## 重建与维护

动画源文件是 [虚拟场景](../scripts/feature-demos.html)，通过 [渲染脚本](../scripts/render-feature-demos.mjs) 导出。场景为本地矢量图形、文字与预设时间轴，不连接应用 API、数据库、外部素材或模型服务。

需要已安装的前端 Playwright 依赖、浏览器以及本机 FFmpeg：

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge' # 本机已安装的 Edge；也可使用 Playwright Chromium
# FFmpeg 不在 PATH 时，可通过 FFMPEG_PATH 指定其可执行文件。
pnpm --dir web exec node ../scripts/render-feature-demos.mjs
```

输出为 `docs/assets/demos/` 下的四张 GIF，分辨率 1080 × 640，10 帧/秒，自动循环。过程帧、源文件摘要、GIF 大小与 SHA256 清单只写入被忽略的 `.cache/harness/animated-demos`。渲染器检查脚本错误、文字越界、GIF 格式和体积；发布前另行解码检查实际帧数、播放时长、循环标志及关键帧排版，并验证 GitHub 上的文件加载。

这些检查验证动画产物，不代替应用业务验收。维护时还需按 [Harness](HARNESS.md) 运行完整检查，把实际证据和限制记录到执行计划；过时的中间帧可在审核后清理，保留可复用源文件与脱敏验证记录。
