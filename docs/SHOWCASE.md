# FoodFlow 模块操作实录

[README](../README.md#从食材开始) 开头先介绍产品与快速开始，中间按「食材、菜单、采购与做饭、记录、家庭、社区」逐步说明日常使用，后面保留更新维护与技术文档。七段实录分散在各自功能文字之后，默认收起，可通过独立的「展开实际操作」逐项查看。这个顺序用于讲解使用过程，应用内的导航顺序保持原样。

本轮素材由[真实操作录制脚本](../scripts/capture-feature-demos.mjs)采集，并经过目视审核。脚本只操作 `127.0.0.1:15173` 的独立验收环境，画面由运行中的 React 应用、Go API 与 PostgreSQL 共同产生；不绘制替代界面，不预设应用返回结果。录制和业务验收是两类证据，录制成功不能代替完整验收。公开的[素材清单](assets/demos/manifest.json)保留源码摘要、操作检查点和每段 GIF 的 SHA256。

## 每段对应一个模块

| 页面入口 | 实际录制的操作 | 确认后的检查 |
| --- | --- | --- |
| 食材 | 打开目录，搜索生菜，填写 50 g，明确确认入库 | 确认前没有生菜库存；确认后 API 与卡片均显示 50 g |
| 菜单 | 浏览菜谱，选择蒜香生菜，安排 1 人晚餐，核对并确认 | 草稿和确认均不改变库存及流水；产生生菜 100 g、蒜 10 g 缺口 |
| 采购 | 打开两项入库确认，核对实购与日期，逐项确认 | 库存达到生菜 150 g、蒜 10 g，两项显示已入库 |
| 今天 | 打开烹饪完成确认，明确提交，刷新页面 | 生菜和蒜均扣至 0 g，刷新后完成状态保留 |
| 记录 | 查看库存流水，切到金额月报，点击导出 | 覆盖说明保留已知与未知成本；实际下载文件具有 PNG 签名 |
| 社区 | 填写标题、用量和步骤，同意初审，提交，收藏并查看详情 | 本地初审返回通过；配方详情保留实际输入用量 |
| 个人中心 | 创建共享家庭，查看空库存，切回个人厨房 | 家庭没有混入个人库存；个人原有番茄 40 g 保留 |

录像按实际速度播放。编码仅调整尺寸、帧率和调色板，不重绘界面、不拼接成功结果，也不删除中间的确认操作。GIF 没有声音；浏览器自身的下载提示可能不出现在视频里，实际月报 PNG 单独保留在录制目录供核对。

## 数据来源与能力边界

脚本通过真实 API 创建新的虚构账号、个人厨房和初始番茄记录。初始番茄为 100 g：先消耗 10 g（此时金额未知），再记录整批 ¥5.00，消耗 20 g、报损 30 g，剩余 40 g。这些是录制前的测试数据，不声称为视频中完成的操作。随后生菜入库、菜单、采购、烹饪、配方发布和家庭创建均通过 UI 执行。

菜单采用手工选择菜谱，不触发收费模型。社区使用隔离环境的本地确定性审核服务，用于展示真实提交与状态流转，不代表真实模型判断。视频不包含真实 ASR、麦克风、照片识别、短信送达、管理员入库或物理手机验收，也不展示用户默认数据库中的私人数据。

目录与菜谱的参考图沿用应用现有素材；这些图片不证明实际库存、新鲜程度或菜品成品。GIF 的虚构数据也不应被解读为真实采购、营养或节省金额。

## 重新录制

先按 [Harness](HARNESS.md) 在已审阅源码上准备隔离验收部署，确认 API、Worker、Web 使用同一份源码绑定镜像。需要前端 Playwright 依赖、Chromium 或 Edge，以及 FFmpeg。

```powershell
# 从仓库根目录执行；仅准备隔离验收账户的正常鉴权预算窗口。
pwsh -File scripts/prepare-browser-fixture.ps1
$env:PLAYWRIGHT_CHANNEL = 'msedge' # 或删除该环境变量，使用 Playwright Chromium
# FFmpeg 不在 PATH 时，用 FFMPEG_PATH 指定其可执行文件。
pnpm --dir web exec node ../scripts/capture-feature-demos.mjs
```

脚本验证 Compose 项目、服务身份和镜像源码标签，检查 Worker 的初审服务只指向本地 fixture，并拒绝启用真实菜单模型的环境。浏览器只访问固定隔离源站，账号凭证不写入清单、不录制密码输入；不会连接默认 `localhost:5173` 数据库，也不会清理任何现有账号、库存或数据卷。

每次录制写到独立的 `.cache/harness/real-feature-demos/<时间>/`：原始 WebM、逐步骤 PNG、实际月报下载、候选 GIF 和 `manifest.json`。GIF 为 960 像素宽、8 帧/秒，保持原始操作速度。清单记录镜像 ID、源码摘要、浏览器版本、关键帧与 GIF 的 SHA256；不包含 token、密码、认证头或接口原始响应。

脚本把产物标记为 `captured-awaiting-visual-review`，不自动复制到公开目录。发布前审查全部关键帧、导出文件和覆盖中间操作的时间序列画面，检查文字清晰、确认步骤可见、输入与结果对应、没有私人信息，然后仅把审核通过的 `intake/plan/shopping/today/report/community/kitchen.gif` 复制到 `docs/assets/demos/`。记录实际审核范围与哈希核对结果，不把抽样审核写成逐帧审查。保留失败录像和必要证据在忽略的缓存目录；不要把整个录制目录提交到 Git。

## 验证范围

录制脚本含数量、草稿不扣库、采购缺口、月报下载、审核状态、家庭隔离和脚本错误检查。完整业务回归仍由 `web/e2e/workflow.spec.ts`、`monthly-report.spec.ts`、`community.spec.ts`、`personal-kitchen.spec.ts` 等场景负责，桌面与移动布局由隔离浏览器验收复查。完整 Harness、默认站点身份、GitHub 当前提交 CI 与任务完成证据应按仓库流程分别记录，不从动图存在推断成功。
